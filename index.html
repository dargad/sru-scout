Blocked SI-4583 LP 2155998 (os-prober) BLOCKED · Bhavya Dokuru

LP: #2155998 · os-prober · Handle invalid grub config entries due to os-prober defaulting unidentified file system types

Issues

  • The reviewer wants the problem understood and reproduced from the boot side before the patch can be judged sensible. The original hanging-mount bug was reportedly solved differently, with mount namespaces, so this change may be unnecessary or wrong.
  • The regression-potential section is wrong. It claims os-prober is disabled by default, but it is enabled automatically when other OSes are detected at install time. A real analysis is also needed of what the fuseblk fallback does, rather than removing it blindly.
  • Unknown filesystems would no longer be probed at all. Legitimate installs on filesystems grub-probe does not recognise, which the fuseblk default may have handled, could silently disappear from the boot menu. This impact is not assessed.
  • The fix is described as needing a backport to Noble and Jammy, which do not yet have the original hang fix. The SRU scope and per-series plan are unclear, and the test plan only covers a Resolute-era setup (the test shows kernel 7.0).
  • The test plan has no verification step showing the snapshot entry is gone after the fix, and it does not check that other filesystem types or other OSes are still detected. It also does not state which series are affected.
  • Development release is not fixed yet
