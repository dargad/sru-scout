Blocked SI-5055 LP 2168803 (qemu) Backlog · Alex Ramírez

LP: #2168803 · qemu · QEMU 8.2.2 guests crash by exhausting vm.max_map_count with coroutines

Issues

  • The backported patches parse /proc/sys/vm/max_map_count incorrectly, so get_global_pool_hard_max_size always returns the default and the limit never takes effect. The fix is only in upstream patches that are not yet merged, and it has not been added to the SRU.
  • The default hard max returned when the limit cannot be read is UINT_MAX. That is effectively unbounded, so the SRU does not cap the pool in that case. The proposed fix is the kernel default of 65530, and it is not yet merged upstream or included in the SRU.
  • The fix reads /proc/sys/vm/max_map_count, which needs a libvirt AppArmor profile change (LP #2170732). A versioned Breaks in qemu is also needed so libvirt gets upgraded. Neither is confirmed done, and without them confined guests may fail or behave differently after the upgrade.
